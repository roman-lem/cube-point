# Cubing SaaS — сервис для локальных сообществ спидкуберов

**Точка сбора** — пет-проект без монетизации. Сервис для клубных встреч: проведение мини-соревнований, ввод результатов участниками со своих устройств, живые таблицы, рекорды клуба и личная статистика. Главная боль, которую решаем, — ручная обработка бланков организатором. Первый клуб — Tyumen | Speedcubing. Цель: рабочий MVP к началу декабря 2026.

**Название сервиса и контакты разработчика** (почта, Telegram, ВКонтакте) задаются в одном месте — `frontend/src/shared/config/site.ts` (`SITE_NAME`, `DEVELOPER_CONTACTS`). Нигде в коде, текстах и `index.html` они не повторяются, только импортируются оттуда.

Владелец проекта сам читает и правит код, поэтому код должен быть простым и понятным, без лишних абстракций. Перед добавлением новой зависимости — спросить.

**Внешние ресурсы.** Никаких ресурсов с внешних доменов (шрифты, CDN, скрипты, аналитика, картинки, запросы к сторонним API) без согласования с владельцем. Причины: встречи проходят в местах с нестабильным интернетом, скорость загрузки, отсутствие трансграничной передачи персональных данных. Всё нужное — в сборке фронтенда (шрифты — пакеты `@fontsource-variable/*`, импорт в `app/main.ts`). Правило закреплено заголовком `Content-Security-Policy` в `frontend/nginx.conf`: при добавлении чего-то нового проверить, что оно работает с ним.

## Стек

- **Фронтенд:** Vue 3 + TypeScript + Vite, Vue Router, Pinia, VueUse. Архитектура FSD. Стили — чистый CSS с CSS-переменными, без UI-фреймворков. Скрамблы и проверка решений FMC — cubing.js.
- **Бэкенд:** Flask, SQLAlchemy, Flask-Login (сессии), Flask-WTF `CSRFProtect`. БД: SQLite на старте, Postgres позже.
- **Инфраструктура:** Docker Compose. Контейнер `web` — nginx со статикой собранного фронта и проксированием `/api/` на контейнер `backend` (`http://backend:5000`). Бэкенд наружу не публикуется. Фронт и API на одном домене, CORS не нужен.
- **Разработка:** прокси Vite (`server.proxy`) на бэкенд, чтобы браузер видел один источник.

## Предметная область

### Роли
- **Участник** — любой вошедший пользователь.
- **Организатор** — право в конкретном клубе (`club_members.role`), а не отдельный тип пользователя. Интерфейс у всех один, организатор видит дополнительные кнопки управления на страницах клуба, встречи и участника.
- **Администратор** — глобальная роль (`users.is_admin`). На этапе MVP только он создаёт сообщества и назначает первого организатора. Клуб без организатора создать нельзя; снятый организатор остаётся участником клуба, последнего организатора снять нельзя. Первый администратор появляется командой `flask make-admin LOGIN` (выдаёт права существующему пользователю или создаёт нового). Ещё администратор обезличивает удалённые аккаунты с сохранённым именем (раздел «Персональные данные»). Эндпоинты — `backend/app/admin.py`.
- Судей нет: участники сами отвечают за честность попыток.
- Человек может состоять в нескольких клубах.

### Встречи
- Раундов, финалов и групп нет. Никогда не показывать «Раунд» или «Финал».
- Каждый участник сдаёт **ровно одну серию** в каждой дисциплине встречи, в своём темпе, от начала до конца встречи.
- Участник может вести **несколько серий одновременно** в разных дисциплинах. Понятия «текущая серия участника» нет, у каждой серии свой статус.
- Скрамблы генерируются при создании встречи и одинаковы для всех участников дисциплины (их можно распечатать на карточках). Скрамблы генерирует приложение, они не официальные — никогда не подписывать их как WCA или официальные. Генерирует их браузер организатора через cubing.js (встречи создаются в основном на десктопе) и отправляет вместе с данными встречи одним запросом; сервер проверяет только их количество по формату, непустоту и длину.
- В соревновательном режиме показывается скрамбл только текущей попытки.
- Попадание на встречу: только по ссылке или QR-коду с `join_token`, который генерирует организатор. По ссылке создаётся заявка `pending`, организатор подтверждает её в панели встречи (есть «Подтвердить всех»). Начать серию можно только со статусом `approved` — проверка на сервере. При первом подтверждении человек автоматически вступает в клуб. Заблокированный в клубе подать заявку не может. Организатор может перевыпустить ссылку; уже подтверждённые участники остаются. После завершения встречи токен недействителен.
- Организатор может вручную добавить участника и вводить результаты за него (для пришедших без телефона); для человека без аккаунта организатор создаёт аккаунт с временным паролем.
- **Завершение встречи** организатором: все несобранные попытки в начатых сериях становятся DNS (отображаются как DNS). Исключение — начатые, но не сданные попытки FMC (см. раздел «FMC»). Не начатые серии не создаются — человек просто не попадает в таблицу дисциплины. Перед завершением диалог показывает, у кого есть незавершённые серии и сколько попыток станут DNS. Завершённая встреча не принимает попытки от участников, но организатор может вносить и править результаты (бумажные бланки).

### Дисциплины и форматы
- Дисциплины — константы в коде с идентификаторами WCA: `333`, `222`, `333oh`, `pyram`, `333fm`, `333bf` (список можно расширять). Для каждой: название, тип результата (время или ходы), формат по умолчанию.
- Форматы: `ao5` (среднее из 5), `mo3` (среднее из 3), `bo3`, `bo5` (лучшая из N), `bo1` (одна попытка). Формат задаётся для каждой дисциплины при создании встречи. По умолчанию: FMC — `bo1`, 3BLD — `bo5`, остальные — `ao5`.
- **ao5:** отбрасываются лучшая и худшая попытки, среднее трёх оставшихся. Один DNF/DNS считается худшей попыткой и отбрасывается; два и более — среднее DNF.
- **mo3:** среднее всех трёх, любой DNF/DNS — среднее DNF.
- **bo3 / bo5 / bo1:** результат — лучшая попытка.
- Средние округляются до сотых в меньшую сторону (тысячные просто отбрасываются).
- В незаконченной серии среднее становится DNF, как только исход предрешён (ao5 — два DNF/DNS, mo3 — один). Остальные попытки всё равно можно дособрать. Иначе, пока серия не закончена, среднего нет («—»).
- В ao5 при равных временах отбрасываются первая из лучших и последняя из худших попыток (на среднее не влияет, только на скобки в AttemptSeries).
- **ao12** — только статистика тренировки, не формат встречи: отбрасываются одна лучшая и одна худшая попытка, среднее десяти оставшихся; один DNF отбрасывается как худшая, два и более — среднее DNF. ao5 и ao12 тренировки считаются по последним 5 и 12 сборкам (`average_of`), скользящие средние по списку сборок — `rolling_averages`.
- Подсчёт: `backend/app/results.py` (источник правды) и `frontend/src/shared/lib/results` (зеркало для живого пересчёта). Обе реализации проверяются общими случаями из `testdata/results_cases.json` — новый случай добавлять туда.
- Логику подсчёта покрыть тестами с граничными случаями с самого начала.

### Таблица дисциплины
Ключ сортировки: для ao5 и mo3 — среднее, затем лучшая попытка; для bo-форматов — лучшая попытка. Любое время лучше DNF. Строки идут тремя группами:
1. Завершённые серии хотя бы с одной удачной попыткой — с местами; при полностью равном ключе место общее (1, 2, 2, 4). DNF-среднее с удачной попыткой — после всех средних, по лучшей попытке.
2. Завершённые серии, где все попытки DNF, — без места («—»).
3. Незавершённые серии — без места, по лучшей попытке, затем по числу сданных попыток.

Внутри равных — по имени. Дисквалифицированные в таблицу не попадают. Подсчёт — `backend/app/scoring.py` (`rank`, `event_table`).

### Время и штрафы
- Время хранится **целым числом в сотых долях секунды**, никаких float. FMC — в ходах (среднее FMC — в сотых долях хода).
- Штраф хранится отдельно от времени (`penalty`: none / plus2 / dnf / dns), не прибавляется к `value`, чтобы его можно было снять.
- В FMC штрафа +2 нет (только DNF/DNS), подсчёт на `plus2` для ходов бросает ошибку.
- Отображение: `9.87`, после минуты `1:02.45`, попытка с +2 — время уже со штрафом и `(+2)`: `11.87 (+2)`, DNF и DNS вместо времени. Во всех местах с цифрами — моноширинный шрифт с табличными цифрами.

### Таймер
- **Тренировочный режим — по умолчанию.** Случайные скрамблы, любая дисциплина, статистика сессии (ao5, ao12, лучшая, число сборок) без сохранения на сервер.
- Тренировочная сессия — своя для каждой дисциплины, хранится в localStorage (`entities/training-session`, ключ `training-session:<event_id>`, формат с полем `version`). Повреждённые данные не ломают страницу: битая сессия или другая версия — пустая сессия, некорректная сборка выбрасывается поштучно. Сборка сохраняется в сессию сразу после остановки, без подтверждения; под таймером — «Последняя: …» с кнопками +2, DNF и удаления. Удаление сборки и «Новая сессия» — с подтверждением. Статистика сессии и список сборок — на вкладке «Статистика».
- Переход к серии требует подтверждения. «Продолжить» у уже начатой серии открывает соревновательный режим сразу, без подтверждения.
- Запуск удержанием и отпусканием (касание на телефоне, пробел на компьютере), опциональная инспекция 15 секунд, режим ручного ввода.
- В соревновательном режиме после каждой сборки время не сохраняется автоматически: участник выбирает OK / +2 / DNF и подтверждает «Сохранить попытку».
- Экран таймера: сверху компактно скрамбл и управление, всё остальное — большая зона для касания. Серии и статистика — на вкладке «Статистика».

### FMC
- 60 минут обратного отсчёта на **каждую попытку** (в mo3 у каждой попытки свой старт и свой час). Старт — с подтверждением, момент старта фиксирует сервер (`fmc_attempts.started_at`), скрамбл сервер отдаёт только после старта. Час строгий, без запаса на сеть.
- Решение вводится с экранной клавиатуры: грани R L U D F B, модификаторы `'` и `2`, переключатель `w` для широких поворотов (`Rw`), перехваты x y z, backspace удаляет один ход.
- Повороты средних слоёв (M, E, S) запрещены — решение с ними DNF.
- Подсчёт ходов по регламенту WCA: повороты граней и широкие повороты — по 1 ходу, включая двойные, перехваты — 0. Решение длиннее 80 ходов — DNF.
- Решение не должно быть получено из скрамбла (регламент WCA). Автоматически ловится очевидное: 6 и более ходов подряд из обратного скрамбла — DNF. Перед сравнением решение переводится в повороты граней в исходной ориентации, так что перехваты и широкие повороты это не обходят. Остальное — на усмотрение организатора, решение сохранено.
- **Никаких индикаторов правильности решения** во время попытки — участник проверяет решение сам. Счётчик ходов не показывается. В FMC нет кнопки копирования скрамбла.
- Черновик решения во время попытки автоматически сохраняется на сервер (`fmc_attempts.draft`), чтобы не потерять его при разряженном телефоне. После дедлайна черновик не принимается.
- Сдача в два шага. «Сдать решение» замораживает текст и время сдачи (`fmc_attempts.frozen_solution`, `frozen_at`) — время фиксируется в момент первого нажатия, чтобы не было DNF из-за диалога. Подтверждение сохраняет попытку с **замороженным** текстом и результатом клиента, `attempts.submitted_at` = `frozen_at`. «Вернуться к решению» снимает заморозку, следующая сдача получит новое время.
- Заморозка после дедлайна (например, из-за плохой сети) всё равно фиксирует присланный текст, но попытка сразу сохраняется как DNF. Если решение верное, DNF снимает организатор.
- Если время вышло без сдачи, результатом становится последний сохранённый черновик: клиент при следующем открытии проверяет его и отправляет результат без подтверждения, `submitted_at` = дедлайн.
- Решение проверяет клиент (`shared/lib/fmc`): применяет скрамбл и решение к виртуальному кубу через cubing.js (собранным считается куб в любой ориентации) и отправляет результат — число ходов или DNF. Проверка запускается только после подтверждения сдачи, а cubing.js подгружается заранее, во время попытки, чтобы сдача не ждала сеть. Причину DNF участник видит после сдачи. Сервер доверяет результату клиента, как и в остальных дисциплинах, но **текст решения всегда сохраняется на сервере** (`attempts.solution`), и организатор может его перепроверить.
- Начатые, но не сданные попытки FMC (сдача заморожена, но не подтверждена; час вышел без сдачи; час ещё идёт) организатор разрешает **до** завершения встречи — сервер не даёт завершить, пока они есть. В диалоге завершения у каждой — скрамбл и решение (замороженное или последний черновик): «Проверить» проверяет решение в браузере организатора тем же `shared/lib/fmc`, «DNF» — засчитывает DNF (не DNS: попытка начата), текст решения сохраняется. Пока час идёт, можно только подождать или поставить DNF. `submitted_at` — момент заморозки или дедлайн.
- Результат участник видит после сдачи вместе с местом в таблице дисциплины.

### Рекорды
- **PB** — личный рекорд человека, считается по всем его встречам во всех клубах, вычисляется запросом.
- **LR** — рекорд клуба (local record), только по встречам этого клуба. Обозначения CR, NR, WR не использовать — это официальные рекорды WCA.
- При равенстве рекорд остаётся за тем, кто поставил его **первым**. Порядок: результат, затем дата встречи, затем момент получения результата (для сингла — `submitted_at` попытки, для среднего — `submitted_at` последней попытки серии).
- `submitted_at` не меняется при правке попытки; время последнего изменения — в `updated_at`. Для рекордов используется только `submitted_at`.
- Рекорды и средние считаются только по текущему значению попытки, журнал (`attempt_history`) на них не влияет.
- `club_records` — кеш. Функция `recalc_records(club_id, event_id)` полностью пересчитывает его из действительных результатов и вызывается из **единственного места, где сохраняются результаты** (`save_attempt` и стирание ошибочного ввода `delete_attempt` в `backend/app/scoring.py`), при любом изменении результатов дисциплины.
- Отметки в таблицах показывают только **актуальные** рекорды: LR — серия держит рекорд клуба, PB — серия держит личный рекорд человека (в том числе самый первый результат). Если у результата оба рекорда, показываются обе отметки.
- Результаты дисквалифицированных на встрече исключаются из таблиц и рекордов.
- Среднее как PB и LR — только у серий в форматах со средним (ao5, mo3); у bo3, bo5 и bo1 есть только сингл. FMC — в ходах, среднее FMC — в сотых долях хода.

### Публичные страницы
- Лендинг в корне сайта и список всех клубов `/clubs` с поиском по названию и городу — из публичного `GET /api/clubs`: название, город, число участников (без заблокированных), число встреч и дата последней (только начатые и завершённые встречи). Сервер отдаёт клубы с самыми недавними встречами первыми, лендинг показывает первые три.
- Рекорды клуба (`/clubs/:id/records`) — из кеша `club_records`, переключатель «Лучшая сборка / Среднее».
- Публичный профиль участника (`/users/:id`): клубы (без тех, где он заблокирован), число встреч, PB по всем клубам и история встреч с попытками, по 10 встреч с подгрузкой. Встречи, где человека дисквалифицировали, в профиле не показываются и в PB не учитываются. Если удачных результатов нет — «—», а не DNF.
- Вкладка «Профиль» — свой публичный профиль с кнопкой «Настройки» (`/profile/settings`: имя и логин только для чтения, смена пароля, администрирование, выход, удаление аккаунта).
- Имена в таблицах результатов и рекордах ведут на профиль, кроме удалённых аккаунтов с сохранённым именем: у них профиля нет, имя без ссылки (`has_profile: false` в `user`, `User.has_profile`), `/api/users/<id>` отвечает 404.
- **Логины на публичных страницах и в публичных эндпоинтах не отдаются**, только `id` и имя. Логин видят организаторы клуба и администратор (и сам пользователь в настройках).
- Эндпоинты — `backend/app/profiles.py`.

### Дисквалификация и блокировка
- **Дисквалификация** — на конкретной встрече, аннулирует все результаты участника на ней (отдельная таблица, серии не удаляются, так что её можно отменить).
- **Блокировка** — в клубе, действует только на будущее: нельзя подавать заявки на встречи. Прошлые результаты и рекорды остаются. Организатора заблокировать нельзя (сначала снять права), себя — тоже.
- Блокировка посреди встречи действует сразу: участник больше не может начать серию, сдать попытку или продолжить FMC (`require_not_banned`), даже на встрече, где он уже подтверждён. Сданные попытки остаются, статусы заявок не меняются, так что разблокировка возвращает всё как было. Незаконченные серии при завершении получают DNS, начатую попытку FMC разрешает организатор. Организатор по-прежнему вводит результаты за заблокированного. Аннулировать результаты — это дисквалификация.
- Обе меры требуют подтверждения с указанием причины.

### Участники клуба
- Список участников (`/clubs/:id/members`) виден всем, без заблокированных: имя, число встреч клуба и текущих LR, строка ведёт на публичный профиль. Организатор и администратор видят и заблокированных, фильтры «Все», «Организаторы», «Заблокированные» и открывают карточку участника: встречи клуба с результатами (переход к правке в `series-edit`), «Доступ» (организатор клуба, сброс пароля), «Нарушения» (дисквалификация на встрече, блокировка). Число встреч — встречи клуба, где у человека есть хотя бы одна серия.
- Недоступные действия не прячутся: карточка приходит с `restrictions` — для каждого действия причина, почему нельзя, или `null`. Эти же проверки выполняют эндпоинты.
- Организатор может снять права с себя, если он не последний организатор.
- «Создать аккаунт» — новичок сразу в клубе, с временным паролем (общий код — `backend/app/accounts.py`).
- Эндпоинты — `backend/app/members.py`.

### Панель организатора
- Ручной ввод и правка: организатор правит любую сохранённую попытку и добавляет следующую по порядку, в том числе начинает серию за участника. Штрафы — none / +2 / DNF / DNS (в FMC без +2). Всё идёт через `save_attempt`. Эндпоинты — `backend/app/desk.py`.
- **Сохранение автоматическое**, одинаково на телефоне и десктопе: ячейка или поле попытки сохраняется при потере фокуса или по Enter. У каждой ячейки видно состояние — сохраняется, сохранено, ошибка с повтором. Кнопок «Сохранить» в ручном вводе нет. Подтверждения требуют только действия, которые нельзя просто переписать следующей правкой: завершение встречи и дисквалификация.
- **Журнал попыток** (`attempt_history`): `save_attempt` при каждом создании и изменении попытки добавляет запись — значение, штраф, решение FMC, кто и когда. Первая запись — исходный результат. Записи не меняются и не удаляются (кроме как вместе со стёртой попыткой); сохранение того же значения записи не добавляет. У исправленной попытки (больше одной записи) — отметка в таблице организатора и в AttemptSeries; исходное значение видят все, полную историю (`…/attempts/<n>/history`) — только организатор. «Вернуть исходный результат» (`…/restore`) — обычная правка через `save_attempt`, тоже попадает в журнал.
- Ошибочный ввод организатор стирает: пустая ячейка или поле, на десктопе ещё Delete / Backspace. Стереть можно только **последнюю** попытку серии — пропуск в середине сломал бы порядок попыток. Попытку, которую сдал сам участник (первая запись журнала — от владельца серии), стереть нельзя, только исправить: иначе пропал бы её журнал. Серия без попыток удаляется, чтобы человек не попал в таблицу и не получил DNS при завершении (если у серии нет начатых попыток FMC — их момент старта сохраняется).
- Ввод в ячейке одной строкой: цифры — время (`1234` → 12.34, `10234` → 1:02.34), «+» — +2, «d» — DNF, «dns» — DNS. На десктопе — навигация стрелками и Enter, «+» и «d» на выделенной ячейке сразу ставят штраф. Разбор — `features/attempt-edit`.
- Сохранения одной серии идут по очереди, чтобы быстрый ввод не давал ложных конфликтов. При конфликте версий сервер возвращает свежие данные дисциплины, строка перезагружается, над таблицей — понятное сообщение.
- Строки таблицы ввода — по имени, а не по месту, чтобы не прыгали во время ввода.
- Добавить участника на встречу (сразу `approved`) можно из участников клуба или новым аккаунтом: временный пароль показывается один раз, `must_change_password`.
- Бланки со скрамблами (`pages/scramble-print`): бланк A5 со всеми скрамблами встречи и полями под попытки, два бланка на листе A4 альбомной ориентации. Бланки одинаковые, число задаётся перед печатью. FMC не печатается — его скрамбл выдаётся только после старта попытки. Разметка бланка пока фиксированная; под будущий редактор раскладки бланк получает данные отдельными props.

### Одновременная запись
Серию может менять и участник, и организатор. У серии есть поле `version`: сохранение отклоняется, если версия изменилась с момента чтения, и клиент перечитывает данные.

## Авторизация

- Вход для всех обязателен, гостевого режима нет.
- Регистрация: имя или никнейм (`display_name`, для таблиц результатов; 2–100 символов: буквы, цифры, пробел и `- ' _ .`, хотя бы одна буква; «Удалённый участник» занять нельзя), логин, пароль и два обязательных согласия. Почта по желанию — привязывается в личном кабинете.
- Регистрацию закрывает переменная окружения `REGISTRATION_OPEN=0`: форма показывает «Регистрация скоро откроется», `POST /register` отвечает 403 `registration_closed`. Вход и создание аккаунтов организатором работают.
- Логины сравниваются без учёта регистра (хранятся в нижнем регистре).
- Логин удалённого аккаунта освобождается (`login = NULL`) и доступен при регистрации новому человеку — в том числе если удалённый оставил имя в результатах.
- Пароли — только хеш на сервере (`generate_password_hash` из Werkzeug). Хеширования на клиенте нет, защита канала — HTTPS.
- Сессии Flask-Login в httpOnly-куке, `SameSite=Lax`, CSRF-токен для изменяющих запросов. Долгая сессия (несколько месяцев) при «Запомнить меня».
- Мгновенный отзыв сессий: `get_id()` возвращает `f"{id}:{session_version}"`, `user_loader` сверяет версию. При сбросе пароля `session_version` увеличивается.
- Восстановление пароля: без почты — организатор клуба сбрасывает пароль и выдаёт временный (показывается один раз, `must_change_password`, `session_version` увеличивается); с почтой — по письму (после MVP). Организатор сбрасывает пароль только тому, кто не организатор ни в одном клубе и не администратор: иначе организатор одного клуба мог бы войти под организатором другого. Пароль организатора сбрасывает администратор. Свой пароль не сбрасывает никто — его меняют в профиле.
- Ограничение числа попыток входа.

### Персональные данные (ФЗ-152)
- **Согласия** — два отдельных: на обработку (`processing`) и на распространение (`publication`: публикация отображаемого имени и результатов в открытом доступе). Хранятся в `user_consents`: тип, версия текста, дата; записи только добавляются. Тексты — отдельными страницами: согласие на обработку — в политике `/privacy` (`pages/privacy`, раздел `#processing`), согласие на распространение — `/publication-consent` (`pages/publication-consent`, ст. 10.1 ФЗ-152 требует оформлять его отдельно). Ссылки на обе страницы — у чекбоксов регистрации и в подвале сайта.
- Версия текста согласия — в `backend/app/consents.py` (`CONSENT_VERSIONS`) и `frontend/src/features/auth/model/consents.ts`. При изменении текста согласия версия меняется в обоих местах: клиент присылает версию, которую показал, сервер принимает только текущую.
- Пользователь без согласий текущей версии (аккаунт создал организатор, обновился текст) получает на любые запросы 403 `consents_required`, кроме входа, выхода, смены пароля, `/auth/consents` и удаления аккаунта. Фронт отправляет его на страницу `/consent`: дать согласия, выйти или удалить аккаунт.
- **Удаление аккаунта** — в настройках профиля, с подтверждением паролем (`POST /api/auth/delete-account`, `accounts.delete_account`). Логин, почта, хеш пароля и согласия уничтожаются, `display_name` становится «Удалённый участник», `deleted_at` заполняется, все сессии отзываются, человек выходит из всех клубов (вместе с членством удаляется причина блокировки). Результаты, журнал, рекорды, заявки и дисквалификации остаются, но причина дисквалификации заменяется на «Причина удалена вместе с аккаунтом»; публичный профиль остаётся с новым именем. Логин освобождается. Последний организатор клуба удалить аккаунт не может, пока не передаст роль (`delete_restriction` в `/me`).
- **Удаление с сохранённым именем.** В диалоге удаления — галочка «Оставить моё имя в результатах и рекордах клубов» (по умолчанию снята; нет, если согласий текущей версии нет). Она означает удаление аккаунта без отзыва данных при регистрации согласий на обработку и распространение — только для отображаемого имени. Логин, почта, хеш пароля и записи согласий уничтожаются как обычно, `display_name` остаётся, а в `user_consents` добавляется запись `deleted_name` с датой и версией последнего согласия на распространение (`keep_name: true` в запросе; без согласия на распространение — 422). Публичного профиля у такого аккаунта нет, имя в таблицах результатов и рекордах — без ссылки. Отзыв — написать разработчику: администратор находит аккаунт на странице «Имена удалённых аккаунтов» (`/admin/deleted-users`, `features/deleted-name`) и обезличивает его с подтверждением: имя становится «Удалённый участник», запись `deleted_name` удаляется, профиль снова открыт, как у обычного удалённого аккаунта.

## Фронтенд

### FSD
Слои сверху вниз: `app`, `pages`, `widgets`, `features`, `entities`, `shared`. Импортировать можно только из нижележащих слоёв. У каждого слайса публичный API через `index.ts`, импорты из глубины слайса запрещены.

- `shared/ui` — элементы без знания о кубинге: AppButton (в том числе кнопка-ссылка с `to`), AppInput, AppCard, PageHeader, LiveIndicator, диалог подтверждения, SettingRow (строка настройки с пояснением, почему действие недоступно), TemporaryPassword (временный пароль с копированием), StepList (нумерованные шаги).
- `shared/config` — название сервиса и контакты разработчика (`site.ts`).
- `shared/lib` — подсчёт результатов серии и форматирование времени (`results`), утилиты. Подсчёт лежит здесь, а не в `entities`, потому что нужен и `attempt`, и `series`, а импорт между слайсами одного слоя запрещён; `entities` реэкспортируют его.
- `entities` — `attempt` (TimeValue, модель попытки), `series` (AttemptSeries, ResultRow), `meetup` (MeetupCard, EventCard), `user`, `club` (ClubCard — карточка в списках клубов), `record` (RecordBadge), `training-session` (тренировочная сессия в localStorage, TrainingStats, TrainingSolveList).
- `features` — вход и регистрация, сдача попытки, старт серии с подтверждением, ввод решения FMC, ручной ввод результатов организатором и история правок попытки (`attempt-edit`), добавление участника на встречу и аккаунт новичка (`participant-add`), завершение встречи (`meetup-finish`), подтверждение заявок, дисквалификация (`disqualification`), блокировка (`member-ban`), права организатора (`member-role`), сброс пароля (`password-reset`), удаление своего аккаунта (`account-delete`), обезличивание удалённых аккаунтов администратором (`deleted-name`). Согласия (чекбоксы, версии текстов) — в `auth`.
- `widgets` — таблица ввода результатов (`results-table`), таймер, клавиатура FMC, нижняя навигация, шапка лендинга (`landing-header`), подвал (`app-footer`, ссылки на политику и согласие на распространение), панель встречи, карточка участника клуба (`member-card`).
- `pages` — экраны (соответствие макетам — в `makets/README.md`).

### Вёрстка
- Все экраны адаптивные, mobile first: базовые стили для узкого экрана, `min-width` медиазапросы для широких. Когда меняются сами компоненты, а не раскладка — `useMediaQuery` из VueUse.
- Стили только через CSS-переменные из `DESIGN.md` (`--color-primary`, `--radius-card`, `--font-mono` и т. д.). Никаких захардкоженных цветов в компонентах.
- Язык интерфейса — русский.

### Навигация
- **Корень сайта** (`/`, маршрут `home`): гость — лендинг; вошедший, который состоит хотя бы в одном клубе, — редирект на страницу клуба своей последней встречи; вошедший без клубов — лендинг, где в герое вместо «Зарегистрироваться» и «Войти» — «Вы вошли как <имя>…». Клуб последней встречи отдаёт `GET /api/auth/home-club` (отдельно от `/me`: он меняется, пока открыто приложение): клуб последней встречи, где заявка человека подтверждена, среди клубов, где он сейчас состоит; если встреч не было — клуб, куда он вступил последним. Решение — `beforeEnter` маршрута в `app/router`.
- Лендинг и страница всех клубов `/clubs` — раскладка лендинга (`meta.layout: 'landing'`): вместо вкладок приложения шапка с названием сервиса и «Войти» (вошедшему — ссылка на профиль), в подвале — строка про бету.
- Гость (без входа): «Клуб», «Рекорды», «Участники», кнопка «Войти» в шапке.
- Вошедший пользователь: «Клуб», «Таймер», «Рекорды», «Статистика», «Профиль». На мобильном — нижняя панель, на десктопе — верхняя.
- Отдельных вкладок «Лайв» и «Митапы» нет: текущая встреча и список встреч — внутри «Клуба», во время встречи на вкладке «Клуб» индикатор LIVE.
- Инструменты организатора — кнопки на страницах клуба, встречи и участника, а не отдельная вкладка. Администрирование — пункт в «Настройках» вкладки «Профиль», виден только администратору.

## Не входит в MVP

Лиги и сезоны, графики прогресса, экспорт данных клуба, импорт старых таблиц, интеграция с WCA и ФС, вход через VK, восстановление пароля по почте, подключение stackmat, офлайн-режим и PWA (архитектуру под них не закрывать), тёмная тема.
