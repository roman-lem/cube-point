# Cubing SaaS — сервис для локальных сообществ спидкуберов

Пет-проект без монетизации. Сервис для клубных встреч: проведение мини-соревнований, ввод результатов участниками со своих устройств, живые таблицы, рекорды клуба и личная статистика. Главная боль, которую решаем, — ручная обработка бланков организатором. Первый клуб — Tyumen | Speedcubing. Цель: рабочий MVP к началу декабря 2026.

Владелец проекта сам читает и правит код, поэтому код должен быть простым и понятным, без лишних абстракций. Перед добавлением новой зависимости — спросить.

## Стек

- **Фронтенд:** Vue 3 + TypeScript + Vite, Vue Router, Pinia, VueUse. Архитектура FSD. Стили — чистый CSS с CSS-переменными, без UI-фреймворков. Скрамблы и проверка решений FMC — cubing.js.
- **Бэкенд:** Flask, SQLAlchemy, Flask-Login (сессии), Flask-WTF `CSRFProtect`. БД: SQLite на старте, Postgres позже.
- **Инфраструктура:** Docker Compose. Контейнер `web` — nginx со статикой собранного фронта и проксированием `/api/` на контейнер `backend` (`http://backend:5000`). Бэкенд наружу не публикуется. Фронт и API на одном домене, CORS не нужен.
- **Разработка:** прокси Vite (`server.proxy`) на бэкенд, чтобы браузер видел один источник.

## Структура репозитория


## Предметная область

### Роли
- **Участник** — любой вошедший пользователь.
- **Организатор** — право в конкретном клубе (`club_members.role`), а не отдельный тип пользователя. Интерфейс у всех один, организатор видит дополнительные кнопки управления на страницах клуба, встречи и участника.
- **Администратор** — глобальная роль (`users.is_admin`). На этапе MVP только он создаёт сообщества и назначает первого организатора.
- Судей нет: участники сами отвечают за честность попыток.
- Человек может состоять в нескольких клубах.

### Встречи
- Раундов, финалов и групп нет. Никогда не показывать «Раунд» или «Финал».
- Каждый участник сдаёт **ровно одну серию** в каждой дисциплине встречи, в своём темпе, от начала до конца встречи.
- Участник может вести **несколько серий одновременно** в разных дисциплинах. Понятия «текущая серия участника» нет, у каждой серии свой статус.
- Скрамблы генерируются при создании встречи и одинаковы для всех участников дисциплины (их можно распечатать на карточках). Скрамблы генерирует приложение, они не официальные — никогда не подписывать их как WCA или официальные. Генерирует их браузер организатора через cubing.js (встречи создаются в основном на десктопе) и отправляет вместе с данными встречи одним запросом; сервер проверяет только их количество по формату, непустоту и длину.
- В соревновательном режиме показывается скрамбл только текущей попытки.
- Попадание на встречу: только по ссылке или QR-коду с `join_token`, который генерирует организатор. По ссылке создаётся заявка `pending`, организатор подтверждает её в панели встречи (есть «Подтвердить всех»). Начать серию можно только со статусом `approved` — проверка на сервере. При первом подтверждении человек автоматически вступает в клуб. Заблокированный в клубе подать заявку не может. Организатор может перевыпустить ссылку; уже подтверждённые участники остаются. После завершения встречи токен недействителен.
- Организатор может вручную добавить участника и вводить результаты за него (для пришедших без телефона); для человека без аккаунта организатор создаёт аккаунт с временным паролем.
- **Завершение встречи** организатором: все несобранные попытки в начатых сериях становятся DNS (отображаются как DNS). Не начатые серии не создаются — человек просто не попадает в таблицу дисциплины. Перед завершением диалог показывает, у скольких участников есть незавершённые серии.

### Дисциплины и форматы
- Дисциплины — константы в коде с идентификаторами WCA: `333`, `222`, `333oh`, `pyram`, `333fm`, `333bf` (список можно расширять). Для каждой: название, тип результата (время или ходы), формат по умолчанию.
- Форматы: `ao5` (среднее из 5), `mo3` (среднее из 3), `bo3`, `bo5` (лучшая из N), `bo1` (одна попытка). Формат задаётся для каждой дисциплины при создании встречи. По умолчанию: FMC — `bo1`, 3BLD — `bo5`, остальные — `ao5`.
- **ao5:** отбрасываются лучшая и худшая попытки, среднее трёх оставшихся. Один DNF/DNS считается худшей попыткой и отбрасывается; два и более — среднее DNF.
- **mo3:** среднее всех трёх, любой DNF/DNS — среднее DNF.
- **bo3 / bo5 / bo1:** результат — лучшая попытка.
- Средние округляются до сотых в меньшую сторону (тысячные просто отбрасываются).
- В незаконченной серии среднее становится DNF, как только исход предрешён (ao5 — два DNF/DNS, mo3 — один). Остальные попытки всё равно можно дособрать. Иначе, пока серия не закончена, среднего нет («—»).
- В ao5 при равных временах отбрасываются первая из лучших и последняя из худших попыток (на среднее не влияет, только на скобки в AttemptSeries).
- Подсчёт: `backend/app/results.py` (источник правды) и `frontend/src/shared/lib/results` (зеркало для живого пересчёта). Обе реализации проверяются общими случаями из `testdata/results_cases.json` — новый случай добавлять туда.
- Логику подсчёта покрыть тестами с граничными случаями с самого начала.

### Время и штрафы
- Время хранится **целым числом в сотых долях секунды**, никаких float. FMC — в ходах (среднее FMC — в сотых долях хода).
- Штраф хранится отдельно от времени (`penalty`: none / plus2 / dnf / dns), не прибавляется к `value`, чтобы его можно было снять.
- В FMC штрафа +2 нет (только DNF/DNS), подсчёт на `plus2` для ходов бросает ошибку.
- Отображение: `9.87`, после минуты `1:02.45`, попытка с +2 — время уже со штрафом и `(+2)`: `11.87 (+2)`, DNF и DNS вместо времени. Во всех местах с цифрами — моноширинный шрифт с табличными цифрами.

### Таймер
- **Тренировочный режим — по умолчанию.** Случайные скрамблы, любая дисциплина, статистика сессии (ao5, ao12, лучшая, число сборок) без сохранения на сервер.
- Переход к серии требует подтверждения. «Продолжить» у уже начатой серии открывает соревновательный режим сразу, без подтверждения.
- Запуск удержанием и отпусканием (касание на телефоне, пробел на компьютере), опциональная инспекция 15 секунд, режим ручного ввода.
- В соревновательном режиме после каждой сборки время не сохраняется автоматически: участник выбирает OK / +2 / DNF и подтверждает «Сохранить попытку».
- Экран таймера: сверху компактно скрамбл и управление, всё остальное — большая зона для касания. Серии и статистика — на вкладке «Статистика».

### FMC
- 60 минут обратного отсчёта, скрамбл появляется только после старта (старт с подтверждением). `series.started_at` — начало отсчёта.
- Решение вводится с экранной клавиатуры: грани R L U D F B, модификаторы `'` и `2`, переключатель `w` для широких поворотов, перехваты x y z, backspace удаляет один ход.
- Повороты средних слоёв (M, E, S) запрещены.
- Перехваты в число ходов не засчитываются (по регламенту WCA; при необходимости сделать настраиваемым).
- **Никаких индикаторов правильности решения** во время попытки — участник проверяет решение сам. Счётчик ходов не показывается.
- «Сдать решение» требует подтверждения, но время сдачи (`attempts.submitted_at`) фиксируется в момент первого нажатия, чтобы не было DNF из-за диалога.
- Если время вышло, а решение не сдано, введённое решение отправляется автоматически в текущем виде.
- Решение проверяет клиент при сдаче: применяет скрамбл и решение к виртуальному кубу через cubing.js и отправляет на сервер решение вместе с результатом (число ходов или DNF). Сервер сохраняет их как есть и решение не перепроверяет — судей нет, участники сами отвечают за честность, а сохранённое решение организатор может пересмотреть. Результат участник видит после сдачи.
- В FMC нет кнопки копирования скрамбла.

### Рекорды
- **PB** — личный рекорд человека, считается по всем его встречам во всех клубах, вычисляется запросом.
- **LR** — рекорд клуба (local record), только по встречам этого клуба. Обозначения CR, NR, WR не использовать — это официальные рекорды WCA.
- При равенстве рекорд остаётся за тем, кто поставил его **первым**. Порядок: результат, затем дата встречи, затем момент получения результата (для сингла — `submitted_at` попытки, для среднего — `submitted_at` последней попытки серии).
- `submitted_at` не меняется при правке попытки; время последнего изменения — в `updated_at`. Для рекордов используется только `submitted_at`.
- `club_records` — кеш. Функция `recalc_records(club, event, user)` полностью пересчитывает его из действительных результатов и вызывается из **единственного места, где сохраняются результаты**, при любом изменении результатов дисциплины.
- Результаты дисквалифицированных на встрече исключаются из таблиц и рекордов.

### Дисквалификация и блокировка
- **Дисквалификация** — на конкретной встрече, аннулирует все результаты участника на ней (отдельная таблица, серии не удаляются, так что её можно отменить).
- **Блокировка** — в клубе, действует только на будущее: нельзя подавать заявки на встречи. Прошлые результаты и рекорды остаются.
- Обе меры требуют подтверждения с указанием причины.

### Одновременная запись
Серию может менять и участник, и организатор. У серии есть поле `version`: сохранение отклоняется, если версия изменилась с момента чтения, и клиент перечитывает данные.

## Авторизация

- Вход для всех обязателен, гостевого режима нет.
- Регистрация: имя и фамилия (для таблиц результатов), логин, пароль. Почта по желанию — привязывается в личном кабинете.
- Логины сравниваются без учёта регистра (хранятся в нижнем регистре).
- Пароли — только хеш на сервере (`generate_password_hash` из Werkzeug). Хеширования на клиенте нет, защита канала — HTTPS.
- Сессии Flask-Login в httpOnly-куке, `SameSite=Lax`, CSRF-токен для изменяющих запросов. Долгая сессия (несколько месяцев) при «Запомнить меня».
- Мгновенный отзыв сессий: `get_id()` возвращает `f"{id}:{session_version}"`, `user_loader` сверяет версию. При сбросе пароля `session_version` увеличивается.
- Восстановление пароля: без почты — организатор клуба сбрасывает пароль и выдаёт временный (показывается один раз, `must_change_password`); с почтой — по письму (после MVP).
- Ограничение числа попыток входа.

## Модель данных

```
users
  id, login (unique, lowercase), display_name, password_hash,
  email (nullable, unique), email_verified, session_version,
  must_change_password, is_admin, created_at, created_by → users

clubs
  id, name, city, timezone, description, logo_path, created_at

club_links
  id, club_id → clubs, type (vk / youtube / site / other), url, position

club_members                     PK (club_id, user_id)
  club_id, user_id, role (member / organizer), joined_at,
  banned_at, banned_by → users, ban_reason

meetups
  id, club_id → clubs, date, starts_at, ends_at, place, address,
  status (planned / live / finished), finished_at, join_token, created_by → users

meetup_participants              PK (meetup_id, user_id)
  meetup_id, user_id, status (pending / approved / rejected),
  requested_at, decided_at, decided_by → users

meetup_events                    unique (meetup_id, event_id)
  id, meetup_id → meetups, event_id, format

scrambles                        unique (meetup_event_id, attempt_number)
  id, meetup_event_id → meetup_events, attempt_number, scramble

series                           unique (meetup_event_id, user_id)
  id, meetup_event_id → meetup_events, user_id → users,
  status (in_progress / completed), started_at, completed_at, version,
  best, average                  (кеш, пересчитывается при сохранении)

attempts                         unique (series_id, attempt_number)
  id, series_id → series, attempt_number, value, penalty,
  solution (FMC), submitted_at, updated_at, entered_by → users

disqualifications                unique (meetup_id, user_id)
  id, meetup_id → meetups, user_id → users, reason, created_by → users, created_at

club_records                     PK (club_id, event_id, type)
  club_id → clubs, event_id, type (single / average), user_id → users,
  value, series_id → series, achieved_at
```

Все метки времени в UTC. Даты и расписание встреч отображаются в часовом поясе клуба (`clubs.timezone`).

## Фронтенд

### FSD
Слои сверху вниз: `app`, `pages`, `widgets`, `features`, `entities`, `shared`. Импортировать можно только из нижележащих слоёв. У каждого слайса публичный API через `index.ts`, импорты из глубины слайса запрещены.

- `shared/ui` — элементы без знания о кубинге: AppButton, AppInput, AppCard, PageHeader, LiveIndicator, диалог подтверждения.
- `shared/lib` — подсчёт результатов серии и форматирование времени (`results`), утилиты. Подсчёт лежит здесь, а не в `entities`, потому что нужен и `attempt`, и `series`, а импорт между слайсами одного слоя запрещён; `entities` реэкспортируют его.
- `entities` — `attempt` (TimeValue, модель попытки), `series` (AttemptSeries, ResultRow), `meetup` (MeetupCard, EventCard), `user`, `club`, `record` (RecordBadge).
- `features` — вход и регистрация, сдача попытки, старт серии с подтверждением, ввод решения FMC, ручной ввод результатов организатором, подтверждение заявок, дисквалификация и блокировка, сброс пароля.
- `widgets` — таблица результатов, таймер, клавиатура FMC, нижняя навигация, панель встречи.
- `pages` — экраны (соответствие макетам — в `makets/README.md`).

### Вёрстка
- Все экраны адаптивные, mobile first: базовые стили для узкого экрана, `min-width` медиазапросы для широких. Когда меняются сами компоненты, а не раскладка — `useMediaQuery` из VueUse.
- Стили только через CSS-переменные из `DESIGN.md` (`--color-primary`, `--radius-card`, `--font-mono` и т. д.). Никаких захардкоженных цветов в компонентах.
- Язык интерфейса — русский.

### Навигация
- Гость (без входа): «Клуб», «Рекорды», «Участники», кнопка «Войти» в шапке.
- Вошедший пользователь: «Клуб», «Таймер», «Рекорды», «Статистика», «Профиль». На мобильном — нижняя панель, на десктопе — верхняя.
- Отдельных вкладок «Лайв» и «Митапы» нет: текущая встреча и список встреч — внутри «Клуба», во время встречи на вкладке «Клуб» индикатор LIVE.
- Инструменты организатора — кнопки на страницах клуба, встречи и участника, а не отдельная вкладка. Администрирование — пункт во вкладке «Профиль», виден только администратору.

### Заглушки
Навигация с самого начала сделана полностью по разделу выше, но не все экраны ещё написаны. Пункты, для которых экрана нет, ведут на общую страницу-заглушку `pages/stub` («Скоро»), чтобы навигация работала целиком и не приходилось переделывать её при добавлении каждого экрана. Сейчас это заглушки:
- «Таймер» (`/timer`) — макеты `timer_training`, `timer_series`, FMC — `fmc_*`;
- «Рекорды» (`/clubs/:clubId/records`) — `club_records`;
- «Статистика» (`/statistics`) — `statistics`;
- «Участники» (`/clubs/:clubId/members`) — для всех список участников клуба, для организатора `org_club_competitors` / `org_competitor_desk`.

«Профиль» пока тоже неполный: на нём только выход и смена пароля, остальное — по макету `profile_settings`.

Когда экран готов: в `app/router` заменить `StubPage` на настоящую страницу и убрать пункт из этого списка. Когда заглушек не останется — удалить `pages/stub` и этот раздел.

## Не входит в MVP

Лиги и сезоны, графики прогресса, экспорт данных клуба, импорт старых таблиц, интеграция с WCA и ФС, вход через VK, восстановление пароля по почте, подключение stackmat, офлайн-режим и PWA (архитектуру под них не закрывать), тёмная тема.
